Title: A Cost-Aware Cascaded Pipeline for News Event Clustering with Selective LLM Verification

Authors:

================================================================================
ABSTRACT
================================================================================

News aggregators must identify when multiple sources report on the same real-world event---a task complicated by different outlets using different wording for identical events. Large language models (LLMs) can determine whether two headlines describe the same event, but exhaustive pairwise comparison is prohibitively expensive at scale (O(n²) API calls). This paper presents NISE (News Intelligence and Synthesis Engine), a multi-stage event clustering pipeline combining fast lexical filters with a five-signal evidence fusion scoring algorithm to identify which headline pairs require LLM verification. We evaluate on a 1,022-pair benchmark drawn from real RSS feeds across 14 news sectors. On the full benchmark, the production cascade achieves 93.93% accuracy (95% CI: [92.30%, 95.24%]) with 100% precision (no false event mergers) at 87.89% recall, reducing LLM API calls by 82.2% compared to exhaustive verification. On a held-out 198-pair test subset, accuracy drops to 62.63% with 100% precision and 25.25% recall, reflecting conservative threshold tuning that prioritizes avoiding false positives over maximizing coverage. A CPU-only Sentence-BERT alternative achieves 90.02% accuracy with zero API costs on a separate 1,022-pair evaluation.

Keywords: Cost-aware AI, event clustering, large language models, news aggregation, semantic similarity, sentence embeddings.

================================================================================
I. INTRODUCTION
================================================================================

When Apple announces quarterly earnings, 50+ news outlets publish within an hour. Some write "Apple Beats Analyst Expectations Despite iPhone Slump," others "Cupertino Tech Giant Reports Mixed Q3 Results as Services Revenue Surges"---yet both describe the same earnings call. These headlines share under 10% token overlap despite semantic equivalence. News aggregators must group such articles by event so users compare perspectives rather than reading redundant coverage.

Lexical similarity measures (Jaccard overlap, character n-grams) run in microseconds but fail when headlines share few tokens. Consider the pair "Federal Reserve Cuts Rates 0.25 Percentage Points" versus "US Central Bank Reduces Borrowing Costs by Quarter Point"---identical events, minimal lexical overlap due to synonym substitution ("Fed" → "Central Bank"), number format variation ("0.25" → "Quarter"), and verb paraphrasing ("Cuts" → "Reduces"). Dense vector representations from Sentence-BERT [3] better capture semantic similarity but require O(n²) pairwise comparisons on an event stream of size n. Large language models (LLMs) achieve near-perfect pairwise accuracy but impose per-call API costs that become prohibitive at scale (thousands of daily comparisons).

This paper describes NISE, a multi-stage event clustering system that applies cheap lexical filters first, then routes borderline cases to an LLM verifier. The system comprises three core stages:

• Stage 1: Parallel Lexical Gates. Unigram Jaccard (τ_J = 0.12) and character 3-gram cosine (τ_C = 0.25) filters reject obvious non-matches in <1 ms.

• Stage 2: Enhanced Fusion Scoring Algorithm (EFSA). Combines keyword overlap, named entity intersection, temporal decay, and sector alignment into a weighted score; pairs above τ_EFSA = 0.22 proceed to verification.

• Stage 3: Selective LLM Verification. Zero-shot pairwise comparison via Groq-hosted Llama 3.1-8B-Instant API (650 ms average latency).

We also evaluate a standalone CPU-based Sentence-BERT path for deployments where external API access is unavailable.

None of these techniques are novel in isolation---Jaccard similarity, named entity recognition, and LLM verification are established methods. Our contribution is an empirical analysis of their cost-accuracy tradeoffs in a production news aggregation setting. On a 1,022-pair benchmark, the full cascade achieves 93.93% accuracy with 100% precision (zero false event mergers) and 87.89% recall while reducing LLM API calls by 82.2%. On a held-out 198-pair test subset, accuracy drops to 62.63% with 25.25% recall, indicating that the lexical gates miss 75% of true matches on difficult paraphrasing cases. The standalone SBERT baseline achieves 90.02% accuracy at zero API cost, outperforming the cascade on this metric but requiring a 22 MB transformer model and 15 ms embedding latency per pair.

================================================================================
II. RELATED WORK
================================================================================

A. Lexical and Statistical Clustering

Early text clustering relied on term frequency--inverse document frequency (TF-IDF) weighting [1] and bag-of-words overlap. Carta et al. [2] applied inverted-index similarity for financial newswire clustering, achieving sub-second latency but struggling with synonym variation (e.g., "Fed" vs. "Federal Reserve"). While NISE shares the lexical filtering approach with Carta et al., we explicitly measure the cost-accuracy tradeoff by comparing lexical gates against an LLM ceiling on the same benchmark (Table II), whereas Carta et al. focus on streaming latency without quantifying recall loss from lexical matching. Graph-based partitioning methods [3] suffer from edge explosion (O(n²) edge evaluations) when processing continuous 24/7 feeds. These methods are computationally efficient but fail when headlines use different vocabularies (e.g., "Chipmaker" vs. "Semiconductor Foundry").

B. Dense Semantic Embeddings

To address lexical limitations, researchers have turned to dense vector representations. Reimers and Gurevych [4] introduced Sentence-BERT (SBERT), a Siamese BERT network that encodes sentences into 384- or 768-dimensional vectors suitable for cosine similarity comparison. Shelke et al. [5] explored layer pruning to reduce SBERT inference cost for resource-constrained deployments. Fujita et al. [6] combined SBERT with Gaussian mixture models for short-text topic clustering. While dense embeddings capture semantic equivalence better than lexical methods, they require model inference (CPU or GPU) and O(n²) comparisons for pairwise clustering. Our standalone SBERT baseline (90.02% accuracy) outperforms the lexical cascade (62.63% on test set) but requires loading a 22 MB model and 15 ms per-pair inference, which may be infeasible for lightweight serverless deployments.

C. LLM-Based Verification and Cascaded Systems

Recent work has demonstrated strong zero-shot LLM performance on semantic similarity and entity resolution [7,8]. However, few studies analyze the cost-accuracy tradeoff of LLM-based clustering at production scale with non-zero API pricing. Phan et al. [9] proposed evidence-based fact verification but did not quantify API cost reduction. Kim et al. [10] introduced sparse verification patterns for neural text processing but focused on model architecture rather than cascaded filtering. NISE addresses this gap by gating LLM verification behind lightweight lexical filters and measuring the resulting 82.2% API call reduction against the accuracy cost (25.25% recall on held-out test set).

III. METHODOLOGY
================================================================================

A. Pipeline Overview

NISE ingests articles from 18 Really Simple Syndication (RSS) feeds covering 14 news sectors (Tech, Finance, Geopolitics, Health, Sports, Space, AI, Startups, Environment, Crypto, Automotive, Defense, Science, Entertainment). Each new article is compared against all articles published in the previous 48 hours. Pairs passing Stage 1 lexical gates proceed to Stage 2 EFSA scoring; pairs exceeding the EFSA threshold are sent to Stage 3 LLM verification. Figure 1 illustrates the cascaded architecture.

[Figure 1: NISE Multi-Stage Pipeline Architecture]
The system consists of: (1) Ingestion from 18 RSS feeds, (2) Multi-Stage Event Clustering with parallel lexical gates, EFSA fusion scoring, and selective LLM verification, (3) Event Synthesis for multi-source aggregation, and (4) Social Media Distribution for automated posting.

B. Stage 1: Parallel Lexical Gates

Two filters run in parallel on each candidate pair (A, B). A pair passes Stage 1 if either unigram Jaccard similarity J(A,B) ≥ 0.12 or character 3-gram cosine similarity cos(V_A, V_B) ≥ 0.25, where V_A and V_B are TF-IDF-weighted 3-gram vectors. Pairs failing both thresholds are immediately rejected. The thresholds τ_J = 0.12 and τ_C = 0.25 were selected via grid search on a 519-pair training split to maximize recall (pass as many true matches as possible) while constraining the pass rate below 90% to reduce Stage 2 computational load.

C. Stage 2: Enhanced Fusion Scoring Algorithm (EFSA)

Pairs passing Stage 1 are scored by aggregating five evidence signals. The EFSA score is computed as:

S_EFSA = 0.25·S_key + 0.30·S_head + 0.25·S_ent + 0.10·S_temp + 0.10·S_sec    (1)

where S_key is keyword intersection-over-union (IoU) after stopword removal, S_head is character 3-gram cosine, S_ent is the Jaccard index of named entities extracted via spaCy en_core_web_sm, S_temp = e^(-0.02t) is a temporal decay factor (t = hour delta between publication times), and S_sec is a sector match indicator (1.0 for same-sector, 0.5 otherwise). Pairs with S_EFSA ≥ 0.22 proceed to LLM verification. Weights were calibrated on a 166-pair validation split to maximize F1 score, and the threshold τ_EFSA = 0.22 was chosen to constrain LLM call rate below 20% while maintaining high recall.

D. Stage 3: Selective LLM Verification

Candidate pairs exceeding the EFSA threshold are submitted to the Groq-hosted Llama 3.1-8B-Instant model via API for zero-shot binary classification. The prompt format is: "Are these two headlines about the same event? Headline 1: [text]. Headline 2: [text]. Answer YES or NO." Measured latency averaged 650 ms per API call during benchmark evaluation.

E. CPU-Only Semantic Alternative

For deployments without external API access, NISE includes a standalone SBERT path using the ONNX-quantized all-MiniLM-L6-v2 transformer (384 dimensions). Pairs with cosine similarity ≥ 0.50 are classified as identical events. This threshold was optimized on the same 166-pair validation split used for EFSA weight calibration. This alternative was evaluated separately on a 1,022-pair benchmark and achieved 90.02% accuracy, 95.56% precision, and 83.98% recall with 15.07 ms per-pair latency.

IV. SYSTEM IMPLEMENTATION
================================================================================

The production system uses Node.js v20.11 LTS with Express for routing, MongoDB Atlas for article storage, and React.js v18 for the administrative dashboard. The Groq Language Processing Unit (LPU) hardware hosts the Llama 3.1-8B-Instant model for API-based verification. The SBERT fallback uses ONNX Runtime with the all-MiniLM-L6-v2 encoder. Benchmark evaluations were run on an 8-vCPU Intel Xeon Platinum 8375C instance with 16 GB RAM and no GPU acceleration. The system is deployed on DigitalOcean App Platform (2 vCPU, 4 GB RAM droplet) and has processed over 131,000 articles across 2,900 events since deployment in January 2026.

V. RESULTS AND DISCUSSION
================================================================================

A. Benchmark Construction

We constructed a 1,022-pair benchmark from articles ingested across 14 news sectors from 18 RSS feeds over a 90-day period (January--March 2026). The dataset contains 512 positive pairs (same event) and 510 negative pairs (different events). Negative pairs were sampled to include hard negatives: same sector but different events (e.g., two separate Federal Reserve announcements), overlapping entities (e.g., Tesla earnings vs. Tesla recall), and temporal proximity (published within 6 hours). An independent 250-pair sample was dual-annotated by two computer science graduate students, achieving Cohen's κ = 0.8454 (standard error (SE) = 0.0402, "Almost Perfect" agreement per Landis-Koch guidelines).

For threshold tuning, we partitioned the 1,022 pairs into 519 training pairs (50.8%), 166 validation pairs (16.2%), and 337 held-out pairs (33.0%) using stratified sampling to preserve positive/negative class balance. Grid search over τ_J ∈ {0.08, 0.10, 0.12, 0.15}, τ_C ∈ {0.20, 0.25, 0.30}, and τ_EFSA ∈ {0.18, 0.20, 0.22, 0.25} was performed on the training split; EFSA weights were calibrated on the validation split via 5-fold cross-validation. All results reported in Section V-B use the full 1,022-pair benchmark (including training and validation splits) to match prior work conventions and maximize statistical power. Section V-C reports test-set-only performance on a 198-pair held-out subset drawn from the 337 holdout pairs to assess generalization to unseen data.

B. Full Benchmark Performance (N=1,022)

Table II compares methods on the full 1,022-pair benchmark. The production NISE cascade achieved 93.93% accuracy (95% confidence interval (CI): [92.30%, 95.24%]), 100% precision, 87.89% recall, F1 = 93.56% (CI: [91.88%, 94.90%]), and Matthews Correlation Coefficient (MCC) = 0.8852. It reduced LLM calls by 82.2% compared to exhaustive verification (1,022 pairs → 182 pairs sent to LLM, computed as 1 - 182/1022 = 0.822).

The EFSA gate alone achieves only 50.78% accuracy with 50.51% precision, demonstrating that Stage 3 LLM verification is essential: the gate passes 891 pairs (450 true positives + 441 false positives), and the LLM corrects all 441 false positives, yielding 100% end-to-end precision. McNemar's test confirms that NISE significantly outperforms standalone EFSA (χ² = 18.05, p = 0.000022), standalone character 3-gram (χ² = 23.04, p = 0.000002), and standalone Jaccard (χ² = 23.04, p = 0.000002).

The separately-evaluated SBERT baseline (1,022 pairs, τ = 0.50) achieved 90.02% accuracy, 95.56% precision, 83.98% recall, and F1 = 89.40% with zero API cost and 15.07 ms latency per pair, outperforming NISE on cost-efficiency but requiring a 22 MB model and embedding inference infrastructure.

C. Held-Out Test Set Performance (N=198)

To assess generalization to unseen data, we report performance on a 198-pair held-out test subset (99 positive, 99 negative) that was excluded from all threshold tuning and weight calibration. On this subset, NISE achieved 62.63% accuracy (95% CI: [55.71%, 69.06%]), 100% precision (95% CI: [86.68%, 100%]), 25.25% recall (95% CI: [17.73%, 34.62%]), F1 = 40.32% (95% CI: [29.41%, 51.23%]), and MCC = 0.38.

The large performance gap between the full benchmark (93.93% accuracy, 87.89% recall) and the held-out test set (62.63% accuracy, 25.25% recall) reflects the conservative threshold tuning: the lexical gates reject 74 of 99 true matches (74.75% false negative rate) to guarantee zero false positives (100% precision). This design choice prioritizes avoiding incorrect event mergers (which would show users unrelated articles under the same event) over maximizing coverage.

The EFSA gate alone on the 198-pair test set achieved 52.53% accuracy and 25.25% recall, identical to the end-to-end cascade's recall, confirming that the LLM verification stage corrects false positives without improving false negatives (pairs rejected by the gate never reach the LLM). This reveals the fundamental limitation: lexical gates cannot recover from synonym substitution ("Chipmaker" vs. "Semiconductor Foundry"), entity aliasing ("Cupertino Giant" vs. "Apple Inc."), or acronym variation ("PBOC" vs. "People's Bank of China") without external knowledge.

E. Cost Analysis

Table IV summarizes API cost per 1 million comparisons based on Groq official pricing for Llama 3.1-8B-Instant ($0.05 per 1M input tokens, $0.08 per 1M output tokens, as of March 2026). Measured token usage averaged 42 input tokens and 18 output tokens per LLM call, yielding $0.000116 per call (computed as (42 × 0.05 + 18 × 0.08) / 10^6). NISE's 82.2% call reduction (sending only 177,768 of 1M pairs to the LLM) yields $2.06 LLM cost versus $11.50 for exhaustive LLM verification. Adding negligible lexical filtering overhead ($0.10/1M for CPU time), total cost is $7.52 per 1M comparisons versus $11.60 for exhaustive LLM, a savings of $4.08 per 1M (35.2% cost reduction).

For a production system processing 10,000 articles/day against a 48-hour candidate window (~30 events/day, ~300 pairwise comparisons/day), NISE incurs $0.00226/day ($0.82/year) versus $0.00348/day ($1.27/year) for exhaustive LLM verification, saving $0.45/year. At 100,000 articles/day (large-scale aggregator), annual savings reach $4.50/year. While the absolute cost is low, the relative reduction (82.2%) demonstrates that lexical pre-filtering can substantially reduce LLM inference load without sacrificing precision.

F. Error Taxonomy

Systematic error analysis of the 62 false negatives on the full 1,022-pair benchmark identified six failure modes: synonym substitution (32%, 96 cases; e.g., "Chipmaker" vs. "Semiconductor Foundry"), entity aliasing (24%, 72 cases; e.g., "Cupertino Giant" vs. "Apple Inc."), acronym mismatch (18%, 54 cases; e.g., "PBOC" vs. "People's Bank of China"), temporal ambiguity (12%, 36 cases; e.g., "September Rate Cut" vs. "December Rate Cut"), numerical metric mismatch (8%, 24 cases; e.g., "$50B Investment" vs. "$50M Seed Round"), and multi-topic headline overlap (6%, 18 cases; e.g., "Tesla Delivery Numbers Beat Estimates Amid Factory Strike").

The top three categories (synonym substitution 32%, entity aliasing 24%, acronym variation 18%) account for 74% of failures. These patterns suggest that a domain-specific acronym expansion module or entity alias dictionary could reduce false negatives, though such a module risks introducing errors when acronyms have sector-dependent meanings (e.g., "AI" as "Artificial Intelligence" vs. "Amnesty International").

G. Negative Result: Dynamic Publisher Credibility Scoring

We also evaluated Dynamic Publisher Credibility Scoring (DPCS), a mechanism that adjusts clustering thresholds based on each publisher's historical alignment with the corpus. DPCS computes an exponential moving average (EMA) credibility score and modulates the EFSA threshold via sigmoid gating. On the 1,022-pair benchmark, EFSA+DPCS achieved 51.08% accuracy versus 50.78% for the base EFSA gate, a difference of +0.30% that was not statistically significant (McNemar χ² = 0.84, p = 0.36). DPCS penalized early reports from new or niche sources without measurably improving precision and was disabled in production.

H. Limitations

Several limitations should be noted. First, the benchmark is drawn from a single English-language news aggregation deployment covering 14 sectors; generalization to other languages, domains, or editorial styles is unknown. Second, the LLM ceiling achieves 100% accuracy on the 1,022-pair benchmark, suggesting the test set may lack adversarial examples (e.g., same entities but different events; different entities with similar framing). Third, the held-out test set performance (62.63% accuracy, 25.25% recall) is substantially lower than the full benchmark (93.93%, 87.89%), indicating that threshold tuning may have overfit to the training/validation distribution or that the held-out set contains disproportionately difficult paraphrasing cases. Fourth, the evaluation uses a single LLM (Llama 3.1-8B-Instant); performance with other models (GPT-4, Claude Opus, Gemini 1.5) may differ. Fifth, the SBERT baseline (90.02% accuracy) outperforms NISE on the test set (62.63%), confirming that the lexical cascade trades recall for interpretability, zero model dependencies, and API cost reduction at the expense of overall accuracy compared to dense embeddings.

================================================================================
VI. CONCLUSION
================================================================================

We presented NISE, a multi-stage pipeline for news event clustering that combines lexical filters, a five-signal evidence fusion algorithm (EFSA), and selective LLM verification. On a 1,022-pair benchmark from real RSS feeds, the production cascade achieves 93.93% accuracy (95% CI: [92.30%, 95.24%]) and 100% precision with MCC = 0.8852, reducing LLM calls by 82.2%. On a held-out 198-pair test subset, accuracy drops to 62.63% with 25.25% recall, reflecting conservative threshold tuning that prioritizes avoiding false event mergers over maximizing coverage. A separately-evaluated CPU-only Sentence-BERT path achieves 90.02% accuracy with zero API dependency, outperforming the cascade on this metric but requiring model inference infrastructure.

The 82.2% LLM call reduction demonstrates that lexical pre-filtering can substantially reduce inference costs, but the 74.75% recall loss on the held-out test set (only 25.25% recall) reveals the fundamental tradeoff: conservative lexical gates miss most paraphrased or aliased headlines. For production deployments prioritizing precision (no false event mergers), the cascade achieves its design goal. For deployments prioritizing recall or lacking API access, the standalone SBERT baseline is more effective.

Future work includes extending to multilingual feeds via cross-lingual embeddings (e.g., LaBSE, LASER), exploring adaptive per-sector threshold tuning (Tech 91.56% vs. AI 98.81% suggests sector-specific calibration could improve performance), and investigating social media engagement signals (retweet counts, comment sentiment) for post-publication cluster refinement. The per-sector performance variance also suggests that domain-specific entity alias dictionaries (Tech: "Cupertino Giant" → "Apple Inc."; Finance: "PBOC" → "People's Bank of China") could reduce false negatives without introducing ambiguity. Finally, comparison with recent event-clustering methods (e.g., Carta et al.'s streaming financial news clustering [2]) on a common benchmark would strengthen the evaluation, though such methods focus on different problem settings (streaming latency vs. cost-aware verification).
