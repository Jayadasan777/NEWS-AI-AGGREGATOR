## Additional P0 finding — Table II combines metrics from incompatible test sets

The current `docs/NISE-Paper-v2.tex` labels Table II as “Comparative Performance on Held-Out Test Split (N=198)”, but several baseline rows match the **N=1,022** RSS-derived evaluation, not the 198-pair split.

**Required repair:** Recompute every comparison row on the same canonical test examples, or present separate tables with explicit dataset/split labels. A table cannot fairly compare NISE on 198 pairs against baselines on 1,022 different pairs.

## Additional P0 finding — Current saved cost analysis conflicts with the manuscript's savings claim

`backend/jobs/evaluation/cost-analysis_real.json` reports these costs and call reductions on `testCases_v2_real.json`:

- LLM-only: $11.60 per million comparisons; 0% calls saved.
- Jaccard gate + LLM: $5.78 per million; 50.8% calls saved.
- Production EFSA gate + LLM: $7.52 per million; **35.6%** calls saved.
- EFSA + DPCS gate + LLM: $6.55 per million; 44.1% calls saved.
- EFSA + SBERT hybrid gate + LLM: $5.19 per million; 55.9% calls saved.

These are not consistent with the 82.3% call reduction in the manuscript. The audit must determine whether 82.3% is from a distinct, reproducible 198-pair experiment or an unsupported extrapolation. Until then, do not generalize it as the production pipeline's call reduction.

## Additional P0 finding — The current cost-per-call arithmetic does not match the cost ledger

At the audit ledger's stated assumed usage (42 input tokens and 18 output tokens), with $0.05 / million input tokens and $0.08 / million output tokens:

`(42 × 0.05 + 18 × 0.08) / 1,000,000 = $0.00000354 per call`.

That equals **$3.54 per million calls** before any additional costs, not $7.52 or $11.60 per million. The latter figures may use different token assumptions and infrastructure components, but those assumptions must be explicit and internally consistent. Also, the checked `cost-analysis_real.json` lists 1M-call totals based on much larger aggregate cost estimates; its stated cost/call assumption should not be silently substituted into that ledger.

## Current conclusion

The existing artifacts are not one internally consistent benchmark package. The safe path is to freeze one data version, produce one held-out prediction file for every baseline and NISE, derive every table directly from those predictions, and only then rewrite the paper's claims.
